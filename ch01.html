CHAPTER 01 · 计算机系统概述

第 1 章 · 先看清整台机器的骨架

组成原理不是“背部件”，而是沿着一条主线往下钻：程序怎样变成指令，指令怎样驱动硬件，硬件又怎样被时间与空间约束。这一章先把整机框架、层次结构和性能语言建立起来，后面六章才有挂靠点。

1.1 从“算盘”到“存储程序”

🍳 生活类比
早期的计算工具像厨房里的一整套手动工具：要做什么菜，人得一步一步操作。冯·诺依曼机的想法是：把菜谱（程序）和食材（数据）一起放进机器，机器自己按菜谱顺序取步骤、取食材、开火翻炒——这就是“存储程序”。

冯·诺依曼在 1945 年提出“存储程序”计算机方案，核心可以压缩成一句话：指令和数据以同等地位存放在同一存储器中，机器按地址访问、按顺序自动执行。它的经典特点有：

五大部件：运算器、控制器、存储器、输入设备、输出设备。运算器 + 控制器 = CPU。
二进制：指令和数据都用二进制表示，存储器不区分“这是指令还是数据”，靠 CPU 的取指/执行阶段来区分。
存储程序：程序事先存入主存，CPU 自动逐条取指执行，不需要人中途拨开关。
指令 = 操作码 + 地址码：操作码说明“做什么”，地址码说明“对谁做”。
顺序执行：默认按 PC 递增的顺序执行，遇到转移指令才改变流程。
以运算器为中心：这是早期结构，输入/输出数据都要经过运算器，现代计算机已改为以存储器为中心，各部件通过总线交换数据。
⚠️ 最容易混淆的一点
“指令和数据同等地位”不等于“CPU 分不清指令和数据”。存储器里确实都存二进制，但 CPU 在取指周期把读出的内容送 IR 当指令译码，在执行周期把读出的内容当操作数使用；阶段决定身份。这也是为什么程序可以被当作数据修改（自修改代码）——但现代系统通常禁止或限制这种做法。

冯·诺依曼 vs 哈佛结构

维度冯·诺依曼结构哈佛结构
存储器指令和数据共用一个存储空间指令存储器与数据存储器分开
总线取指和取数可能争用同一总线（结构冒险）可同时取指和取数，带宽更高
典型场景通用计算机主存单片机、DSP、CPU 的 L1 指令/数据 Cache

现代 CPU 常见的是“混合结构”：主存统一编址（冯·诺依曼），但 L1 Cache 分成 I-Cache 和 D-Cache（哈佛），兼顾灵活性与取指/取数并行。

1.2 一条指令是怎样跑完的

先把 CPU 内部四个关键寄存器记住，后面第 5 章会反复用：

寄存器全称作用易错点
PC程序计数器存放下一条要执行的指令地址不是“当前指令地址”；取指后通常自动加指令长度
IR指令寄存器存放当前正在译码/执行的指令IR 的内容供译码器使用，不直接参与地址计算
MAR存储器地址寄存器存放要访问的主存单元地址位数决定可寻址空间
MDR存储器数据寄存器存放从主存读出或要写入主存的数据位数通常等于存储字长

以一条“加法”指令为例，CPU 的典型执行过程是：

取指（IF）：PC → MAR；MAR 送地址到主存；主存读出指令 → MDR → IR；PC 更新为下一条指令地址。
译码（ID）：译码器分析 IR 中的操作码，判断这是加法、访存还是转移；同时读出寄存器操作数。
取操作数（OF）：若操作数在主存，按寻址方式算出有效地址，访问主存送入 MDR。
执行（EX）：ALU 完成运算，结果暂存；若为访存指令，则计算地址或准备写数据。
写回（WB）：把结果写回寄存器或主存；若为转移指令，则修改 PC。
📌 408 高频：取指数据流
PC → MAR → 主存 → MDR → IR，同时 PC + “1” → PC。这里的“1”不是固定 1 个字节，而是一条指令的长度；在按字编址、指令字长为一个字时才是加 1。选择题常把“PC 加 1”写成固定加 1 来设陷阱。

为什么要把“取指”和“执行”分开？因为它们的访存行为不同：取指访存取的是指令，执行访存取的是数据；分开后控制器可以按周期发出不同的控制信号，也方便引入流水线（第 5 章）。

1.3 软件、硬件与多级层次

计算机系统 = 硬件 + 软件。软件通常分为：

系统软件

操作系统、编译程序、汇编程序、链接程序、数据库管理系统等。它管理硬件资源，为应用软件提供运行环境。

应用软件

浏览器、办公软件、游戏、各类业务系统。它面向具体任务，运行在系统软件之上。

从“机器能直接执行什么”看，又可以把系统分成多级层次：

层次名称这一层看到的世界由谁实现
M4高级语言级C、Java、Python 等编译程序 / 解释程序
M3汇编语言级助记符、标号、伪指令汇编程序
M2操作系统级系统调用、进程、文件操作系统
M1传统机器级机器指令（ISA）硬件 / 微程序
M0微程序机器级微指令、微操作硬件
🔍 “透明”是什么意思
在计算机体系结构中，“透明”指存在但上层看不见。例如微程序对机器语言程序员透明：写机器指令的人不需要知道微指令怎么编。注意不是“不存在”，也不是“看不见所以不重要”。

编译 vs 解释：编译程序把高级语言源程序整体翻译成目标程序，之后可反复执行；解释程序逐条翻译并立即执行，通常不生成独立目标文件。编译执行快、但多一步构建；解释灵活、但运行时开销大。汇编程序则是把汇编语言翻译成机器语言。

1.4 性能指标：别只会背主频

408 常考的性能指标可以分成“时间类”和“吞吐类”：

指标含义公式 / 单位备注
机器字长CPU 一次整数运算能处理的二进制位数位（bit）通常等于通用寄存器宽度，如 32/64 位
时钟周期CPU 主频的倒数T = 1 / f单位 ns（1 GHz → 1 ns）
CPI每条指令平均时钟周期数总周期数 / 指令数不同指令 CPI 不同，程序混合后取平均
CPU 时间程序在 CPU 上执行的时间指令数 × CPI × 时钟周期也写成 指令数 × CPI / 主频
MIPS每秒执行多少百万条指令主频(MHz) / CPI只适合定点指令，不适合浮点
MFLOPS每秒多少百万次浮点运算浮点操作数 / (时间 × 10⁶)衡量科学计算性能
吞吐量单位时间完成的任务数任务数 / 时间与响应时间不是一回事
响应时间完成单个任务所需时间秒交互体验更关注它
CPU 时间 = 指令数 × CPI × 时钟周期 = 指令数 × CPI / 主频
MIPS = 主频（MHz）/ CPI = 指令数 /（执行时间 × 10⁶）
平均 CPI = Σ（第 i 类指令的 CPI × 第 i 类指令所占比例）

例：某 CPU 主频 2 GHz，平均 CPI = 4，程序执行 10⁸ 条指令。则：

时钟周期 = 1 / 2 GHz = 0.5 ns
CPU 时间 = 10⁸ × 4 × 0.5 ns = 0.2 s
MIPS     = 2000 MHz / 4 = 500
⚠️ 主频高 ≠ 性能好
① CPI 不同：A 主频 3 GHz、CPI 6，B 主频 2 GHz、CPI 2；同样 10⁸ 条指令，A 用 0.2 s，B 只用 0.1 s。
② 指令集不同：完成同一任务，RISC 可能需要更多条指令，CISC 一条指令做更多事，不能只比主频。
③ 程序不同：跑分程序偏向某类指令，不能代表所有负载。
④ 存储墙：CPU 很快但主存跟不上，实际性能受 Cache 命中率和内存带宽限制。

Amdahl 定律：优化一部分，收益有上限

若某部分占总执行时间的比例为 p，把这部分加速 s 倍，则整体加速比为：

加速比 = 1 / ((1 − p) + p / s)

例如程序 40% 的时间在乘法上，把乘法加速 4 倍，整体加速比 = 1 / (0.6 + 0.4/4) = 1 / 0.7 ≈ 1.43。剩余 60% 不优化，整体就不可能超过 1/0.6 ≈ 1.67 倍。这也是“木桶效应”的定量版本。

🔬 实验室：性能指标换算器

改主频、CPI、指令数，看 CPU 时间与 MIPS 怎么变。重点观察：主频翻倍但 CPI 也翻倍时，时间不变。

🚀 进阶深挖（教材级）

深挖 1 · 冯·诺依曼瓶颈与存储层次

CPU 与主存之间只有一条（或有限几条）通路，而 CPU 的速度增长远快于 DRAM，导致“CPU 等数据”。解决思路有两条：一是用 Cache—主存—辅存 的存储层次，把常用数据放在离 CPU 更近的地方；二是用多体交叉、宽总线提高主存带宽。第 3 章会展开。

深挖 2 · CPI 的分解与“指令混合”

程序的平均 CPI 不是某一类指令的 CPI，而是按指令比例加权：

CPI平均 = Σ (CPIi × fi)，其中 Σ fi = 1

例如 load 占 30%、CPI=4；运算指令占 50%、CPI=1；分支占 20%、CPI=2，则平均 CPI = 0.3×4 + 0.5×1 + 0.2×2 = 2.1。编译器优化、指令集设计都会改变 fi，所以“换编译器”也可能带来性能差异。

深挖 3 · 性能评价：基准程序与几何平均

用一两个小程序测性能容易被“针对优化”。常见做法是跑一组基准程序（如 SPEC），再对多个程序的加速比取几何平均：

几何平均 = (∏ 加速比i)1/n

几何平均对“比例变化”更公平；算术平均会被某个特别大的值拉偏。408 一般只考概念，不要求复杂计算。

🌐 多源视角
  • 【唐朔飞《计算机组成原理》】把机器分为“微程序机器级—传统机器级—操作系统级—汇编语言级—高级语言级”，强调每一级都向上一级提供接口。本站用法：看到“透明”先问“对哪一级透明”。
  • 【CSAPP】用“程序员视角”讲机器：程序从源文件到可执行文件，要经过预处理、编译、汇编、链接。本站用法：把“编译”与“汇编”分清，选择题常混。
  • 【Patterson & Hennessy】用“性能 = 1 / 执行时间”统一度量，并把 CPU 时间拆成指令数、CPI、时钟周期三个因子。本站用法：任何性能题先写出这三个因子，再找题目给了哪两个。
参考：唐朔飞《计算机组成原理》（第 3 版）第 1 章；CSAPP 第 1、7 章；Patterson & Hennessy《Computer Organization and Design》第 1 章。

⚠️ 本章避坑清单

“存储程序”指程序和数据一起存在同一主存，不是“程序存在硬盘上”。硬盘上的程序要先装入主存才能执行。
PC 存的是下一条指令地址；取指后加的是“指令长度”，不是无脑加 1。
机器字长 ≠ 指令字长 ≠ 存储字长。三者可以不同，题目给“某机字长 32 位”通常指机器字长。
MIPS 只反映定点指令吞吐，不能拿来比较浮点性能；浮点看 MFLOPS。
“主频高一定快”是错的；要结合 CPI、指令数、存储层次和程序负载。
编译程序生成目标代码，解释程序通常不生成独立目标代码；不要把“解释”说成“编译后执行”。
