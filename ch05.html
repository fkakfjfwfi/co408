CHAPTER 05 · 中央处理器

第 5 章 · 指令在这里变成电信号

CPU 是计组的“心脏”：取指、译码、执行、访存、写回，每一步都要有数据通路和控制信号配合。这一章的重点不是背框图，而是能沿着一条指令走完整个数据通路，并能画流水线时空图。

5.1 CPU 结构：运算器 + 控制器 + 寄存器

🏭 生活类比
CPU 像一座工厂：运算器是车间，控制器是调度室，寄存器是手边的小料盒，Cache/主存是仓库。调度室按订单（指令）发工单（控制信号），车间从料盒取料加工，成品再放回料盒或仓库。

运算器

部件作用备注
ALU算术/逻辑运算加减、与或非、移位、比较
ACC累加器存放一个操作数或结果
MQ / X乘商寄存器 / 操作数寄存器乘除法时配合 ALU
通用寄存器存放操作数/地址R0~Rn，减少访存
PSW程序状态字ZF、SF、OF、CF、中断允许位等

控制器与关键寄存器

寄存器作用易错点
PC下一条指令地址取指后按指令长度更新
IR当前指令操作码送译码器，地址码送地址形成部件
MAR主存地址位数决定寻址空间
MDR主存数据与总线/存储字长相关
时序系统产生时钟/节拍控制微操作按时间顺序执行

CPU 与主存之间通过地址总线、数据总线、控制总线连接。MAR 的输出接地址总线，MDR 与数据总线双向连接；控制总线传送读/写、中断、总线请求等信号。

5.2 指令周期：一条指令的四个阶段

指令周期 = 取指周期 +（间址周期）+ 执行周期 +（中断周期）

括号表示可选：只有间接寻址才需要间址周期；只有响应中断时才进入中断周期。每个周期又由若干机器周期/时钟周期组成。

阶段主要动作访存结束时
取指（IF）PC→MAR，读主存，MDR→IR，PC 更新读指令IR 中有了指令
间址（IND）按 IR 的地址字段读主存，得到有效地址读 EA地址寄存器/暂存器有了 EA
执行（EX）取操作数、运算、写回；或计算转移地址可能读/写数据结果写回，或 PC 改变
中断（INT）保存断点，转中断服务程序保存现场进入服务程序
📌 取指的“PC+1”到底加多少
取指后 PC 加的是一条指令的长度。若指令字长 = 存储字长 = 1 个字，且按字编址，才是 PC+1；若指令字长 32 位、按字节编址，则是 PC+4。题目常在这里设陷阱。

5.3 数据通路：控制信号指挥的“交通网”

数据通路是寄存器、ALU、存储器之间传送数据的路径。按总线数量可分为单总线、双总线、三总线结构。单总线结构同一时刻只能有一个数据传送，因此一条指令需要多个时钟周期；多总线可以并行传送，速度更快但成本更高。

单总线结构下的一条加法指令

// 指令：ADD R1, R2   （R1 ← R1 + R2）
// 取指周期
PC → MAR
M(MAR) → MDR
MDR → IR
PC + 1 → PC

// 执行周期（单总线，分步）
R1 → A          // 操作数 1 送 ALU 的 A 端
R2 → B          // 操作数 2 送 ALU 的 B 端
A + B → R1      // ALU 结果写回 R1
🔬 实验室 2 · 单总线数据通路步进
以 ADD R1, R2 为例，点“下一步”看每一步是哪两个部件在使用总线；高亮的就是当前传送的两端。

每一步都需要控制器发出对应的控制信号（如 PCout、MARin、MemR、MDRout、IRin）。数据通路大题常要求你写出微操作序列并标注控制信号，答题时按“取指—取数—运算—写回”分段，不要漏掉 PC 更新。

取指阶段的统一性

无论什么指令，取指阶段的数据流都一样：PC → MAR → 主存 → MDR → IR。这是控制器设计的基础：取指微程序可以被所有指令共享。执行阶段才根据操作码走不同分支。

5.4 控制器：硬布线 vs 微程序

维度硬布线控制器微程序控制器
实现组合逻辑电路直接产生控制信号控制信号以微指令形式存放在控制存储器
速度快较慢（要取微指令）
设计/修改复杂，修改困难规整，易修改/扩展指令
适用RISC、简单指令集CISC、复杂指令集
典型定长指令、流水线 CPUx86 风格的复杂指令

微程序控制器的核心概念

微命令：控制部件发出的最小控制信号，如“打开 PC 输出门”。
微操作：微命令执行的具体动作，如“PC 内容送总线”。
微指令：若干微命令的组合，格式通常为“控制字段 + 下地址字段”。
微程序：完成一条机器指令的微指令序列，存放在控制存储器（CM）中。
微地址：下一条微指令在 CM 中的地址，可由下地址字段、操作码映射或断定方式产生。

微指令的两种格式

类型特点优点缺点
水平型微指令一次可并行发出多个微命令，字长长并行能力强、微程序短、执行快微指令字长，控制存储器容量大
垂直型微指令类似机器指令，一次控制少量微操作，字短微指令短、规整并行性差、微程序长

微命令编码

方式做法特点
直接编码每一位对应一个微命令速度快，但字长长
字段直接编码互斥微命令放同一字段，译码后产生缩短字长，需译码时间
字段间接编码一个字段的含义由另一个字段解释进一步缩短字长，控制更复杂

互斥性是字段划分的关键：同一字段里的微命令不能同时有效，否则译码后无法区分。例如“读寄存器”和“写寄存器”可以放在不同字段，因为它们可能同时需要；而“PC 输出”和“R1 输出”如果都接到同一总线，就应放在同一字段互斥。

5.5 流水线：让多条指令同时在路上

🏭 生活类比
流水线像洗车：喷水、打泡、擦洗、冲净、烘干五个工位。第一辆车在打泡时，第二辆车已经在喷水。虽然每辆车仍要经过五道工序，但整体每小时能洗更多车。

经典五段流水线：

段名称主要工作
IF取指按 PC 读指令，PC 更新
ID译码/读寄存器译码，读通用寄存器，计算立即数
EX执行ALU 运算，计算有效地址
MEM访存读/写数据存储器
WB写回结果写回寄存器

设流水线有 k 段，执行 n 条指令，每段耗时 Δt，且无冒险，则：

总时间 T = (k + n − 1) × Δt
吞吐率 TP = n / T
加速比 S = nk / (k + n − 1)
效率 E = S / k = n / (k + n − 1)

当 n → ∞ 时，S → k，E → 1。流水线的理论上限是“k 倍”，实际会被冒险、流水线寄存器开销、时钟偏斜拉低。

设置指令条数，生成五段流水线时空图；勾选“插入 2 个停顿”，观察总周期与加速比的变化。

三类冒险与解决办法

冒险原因典型例子解决办法
结构冒险多条指令争用同一硬件资源IF 和 MEM 同时访问统一 Cache；寄存器文件端口不够分离 I/D Cache；增加端口；停顿
数据冒险后一条指令依赖前一条尚未写回的结果add r1,r2,r3 后紧跟 sub r4,r1,r5转发/旁路；停顿；编译器调度；寄存器重命名
控制冒险分支指令改变 PC，下一条指令不确定beq、jmp、函数返回分支预测；延迟槽；提前计算目标地址；BTB
⚠️ load-use 冒险：转发也不够
lw r1, 0(r2) 后紧跟 add r3, r1, r4：load 的数据要到 MEM 段末才可用，而 add 在 EX 段就需要，即使有转发也必须停顿 1 个周期。这是考试常考的“转发不能完全消除的冒险”。

流水线进阶概念

概念含义
超标量（superscalar）每个时钟周期发射多条指令，需要多个功能部件和更复杂的调度
超流水（superpipelining）把每段再细分，提高时钟频率，但冒险/开销增加
动态调度/乱序执行硬件在运行时调整指令顺序，减少停顿；需要重排序缓冲保证提交顺序
寄存器重命名消除假数据依赖（WAR/WAW），让更多指令并行

5.6 多核与多处理器（概念）

多核处理器把多个 CPU 核集成在一个芯片上，共享 L3 Cache 和主存。核间通过共享存储或消息传递通信；共享数据需要缓存一致性协议（如 MESI）保证各核看到的值一致。408 对多核的要求以概念为主：能说出“多核并行、共享 Cache、一致性、核间同步”即可。

🚀 进阶深挖（教材级）

深挖 1 · 单总线数据通路的微操作序列

单总线结构中，每个时钟周期只能有一个部件把数据放到总线上。写微操作序列时遵循：源部件 out、目的部件 in、ALU 功能选择、存储器读/写四类信号。以 ADD R1, R2 为例：

T1: PCout, MARin, PC+1
T2: MemR, MDRin
T3: MDRout, IRin
T4: R1out, Ain
T5: R2out, Bin
T6: ALUadd, R1in

实际题目可能要求把取指和执行合并到若干机器周期，按题目给出的节拍写，不要机械套用。

深挖 2 · 微程序的执行过程

取机器指令 → 操作码映射到微程序入口 → 从 CM 取微指令 → 微指令的控制字段产生微命令 → 下地址字段/断定逻辑产生下一条微地址 → 重复直到微程序结束 → 取下一条机器指令。微程序控制器也需要“取微指令—执行”的循环，只是它的“指令”更底层。

深挖 3 · 流水线性能的修正

理想公式假设各段等长、无冒险、无开销。实际中：时钟周期取最慢段 + 流水线寄存器延迟；分支会带来惩罚；Cache 缺失会让 IF/MEM 停顿；多发射会改变“每条指令占几拍”的定义。做题时先看题目是否声明“理想流水线”，没有声明就按给出的段数和停顿数算。

🌐 多源视角
  • 【唐朔飞】先讲指令周期，再讲数据通路，最后讲控制器；强调“取指阶段所有指令共用”。本站用法：画数据通路题先写取指，再写执行，不会乱。
  • 【CSAPP】用 Y86-64 循序渐进地搭 CPU：先单周期，再流水线，最后处理冒险。本站用法：把“控制信号—数据通路—流水线寄存器”看成一条链，别孤立背。
  • 【Patterson & Hennessy】用“流水线时空图 + 冒险”讲性能，强调 load-use 需要停顿。本站用法：看到 load 后紧跟使用，先想“能不能转发，需不需要停”。

⚠️ 本章避坑清单

PC 存下一条指令地址；取指后加指令长度，不是固定加 1。
间址周期取的是有效地址，不是操作数；执行周期才取操作数。
硬布线速度快但难修改，微程序灵活但需要取微指令；不要反着说。
水平型微指令并行强、字长长；垂直型字短、并行差。选择题常把优缺点对调。
流水线总周期 = k + n − 1，不是 n × k；加速比上限是 k，不是无限。
load-use 冒险即使有转发也可能要停 1 拍；不要看到“转发”就认为零停顿。
结构冒险是资源冲突，数据冒险是数据依赖，控制冒险是分支改变 PC；三者不要混。
