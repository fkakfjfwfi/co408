第 7 章 · CPU 不可能一直等设备

I/O 系统的核心矛盾是速度差：CPU 纳秒级，外设毫秒级。程序查询让 CPU 干等，中断让设备主动通知，DMA 让控制器接管数据块——这一章就是一条“把 CPU 解放出来”的演进路线。

7.1 I/O 接口：CPU 与外设之间的“翻译 + 缓冲”

🌉 生活类比
I/O 接口像海关：一边是 CPU（快、规则统一），一边是各种外设（慢、格式各异）。海关负责排队缓冲、检查证件（状态）、翻译格式、决定放行（控制），让两边不必直接适配。

外设为什么不能直接接 CPU？因为存在四类差异：速度差异、数据格式差异、时序差异、电气特性差异。I/O 接口负责弥合这些差异。

功能说明
数据缓冲用数据寄存器暂存，解决 CPU 与外设速度不匹配
速度匹配/时序控制按外设时序控制数据传送
格式转换串/并转换、电平转换、字节/字组装
状态检测与控制提供状态寄存器（就绪/忙/错误）和控制寄存器（启动/命令）
地址译码与设备选择根据地址选中相应端口
中断/DMA 支持产生中断请求或 DMA 请求

接口内部结构与端口

典型接口包含：数据寄存器（数据端口）、状态寄存器（状态端口）、控制寄存器（控制端口）、地址译码逻辑、控制逻辑。CPU 通过不同的端口地址访问它们。

编址方式做法优点缺点
统一编址（存储器映射 I/O）端口与主存共用地址空间可用普通 load/store 指令，编程灵活占用主存地址空间；译码较复杂
独立编址（I/O 映射）端口有独立地址空间，用专用 I/O 指令不占主存空间；I/O 指令短需要专用指令；编程不如统一编址灵活

7.2 程序查询：最简单的“干等”

启动设备：CPU 向控制寄存器写命令，启动外设。
读状态：CPU 反复读取状态寄存器，检查“就绪/完成”位。
忙等：若未就绪，继续读状态，CPU 不能做别的事。
传送：就绪后，CPU 从数据寄存器读数或写数据。
循环：处理下一个数据/设备。

优点：硬件简单、程序直观，不需要中断/DMA 控制器。
缺点：CPU 与外设串行工作，设备慢时 CPU 大量时间在忙等；多个设备时更糟。适合设备速度较快、CPU 任务不重或嵌入式简单场景。

7.3 中断：让设备主动“举手”

中断让外设在准备好时主动通知 CPU，CPU 不必轮询。一次完整的中断过程包括：中断请求 → 中断判优 → 中断响应 → 中断服务 → 中断返回。

中断的分类

分类来源例子特点
外中断（可屏蔽）外部设备键盘、网卡、磁盘可通过中断允许位屏蔽
外中断（不可屏蔽）外部紧急事件电源故障、复位不受中断允许位控制
内中断（异常）CPU 内部除零、缺页、非法指令、断点与当前指令相关
软件中断指令int n、系统调用程序主动触发

中断响应：硬件自动完成的“隐指令”

关中断：清除中断允许触发器，防止响应过程被新中断打断。
保存断点：把当前 PC（下一条指令地址）和 PSW 保存到栈或指定单元。
识别中断源：通过中断判优/编码确定是哪个设备，取得中断类型号。
取中断向量：按类型号查中断向量表，得到服务程序入口地址。
转服务程序：把入口地址送 PC，开始执行中断服务程序。
⚠️ 中断隐指令不是“一条指令”
它没有操作码，不占指令系统的一条指令，而是 CPU 在中断响应周期由硬件自动完成的操作序列。不同教材对“保存 PSW”归属（隐指令 vs 服务程序）有差异，答题时按题目教材口径，核心是“关中断、保存断点、识别中断源”。

中断判优与中断嵌套

判优：多个中断源同时请求时，按优先级决定先响应谁。可用硬件排队器（如链式、独立请求）或软件查询顺序实现。

中断嵌套：高优先级中断可以打断正在执行的低优先级服务程序。是否允许嵌套由屏蔽字控制：每个中断源有一个屏蔽字，服务程序设置它，屏蔽本级及更低优先级，开放更高优先级。单重中断则在整个服务程序期间关中断，不允许嵌套。

中断向量表：存放各中断类型对应的服务程序入口地址（及 PSW）。CPU 用中断类型号作为索引查表，不需要为每个设备写死入口。

7.4 DMA：让控制器直接搬数据

中断方式下，每传一个数据（或一小批）CPU 都要停下当前工作去处理，高速块设备仍然吃不消。DMA（Direct Memory Access）让 DMA 控制器直接在主存与外设之间搬运数据块，CPU 只在开始和结束时参与。

DMA 控制器的组成

部件作用
主存地址寄存器存放当前要访问的主存地址，每传一个字自动加/减
字计数器记录剩余传送字数，减到 0 表示完成
数据缓冲寄存器暂存传送的数据
控制/状态逻辑产生 DMA 请求、总线请求，接收命令和状态
中断机构传送完成后向 CPU 发中断

DMA 传送过程

初始化：CPU 设置 DMA 控制器的源地址、目的地址、传送长度、方向。
设备请求：外设准备好后向 DMA 控制器发 DREQ。
总线请求：DMA 控制器向 CPU 发 HRQ，申请总线使用权。
传输：CPU 让出总线（或周期挪用），DMA 控制器直接读写主存，地址/计数自动更新。
完成：计数到 0，DMA 控制器发中断，CPU 做校验、切换缓冲区等收尾。

DMA 的三种传送方式

方式做法优点缺点
停止 CPU 访存DMA 独占总线，CPU 停止访存控制简单，传送快CPU 可能长时间不能访存
周期挪用（周期窃取）DMA 趁 CPU 不访存的周期占用总线CPU 只被少量减速控制较复杂，可能争用
DMA 与 CPU 交替访问按时间片交替使用总线两者都有机会，较平衡需要时间片控制，效率受限制

DMA vs 中断

维度中断方式DMA 方式
触发者设备发中断请求给 CPU设备发 DMA 请求给 DMA 控制器
数据传送CPU 执行服务程序逐字/逐块传送DMA 控制器直接传送，CPU 不介入
CPU 开销每个数据/事件都要中断只在初始化和结束时参与
适用中低速、随机事件高速块设备（磁盘、网卡）
优先级由中断优先级决定DMA 请求通常优先于 CPU 访存

7.5 通道、I/O 处理机与磁盘

通道（channel）是专门负责 I/O 的处理器，能执行通道程序，控制多台设备与主存之间的数据传送。CPU 只需发一条 I/O 指令启动通道，通道完成后中断 CPU。它进一步减少了 CPU 对 I/O 的干预。

I/O 处理机比通道更独立，有自己的指令系统和存储器，可以执行更复杂的 I/O 程序，CPU 几乎不参与。

方式CPU 参与程度数据传送单位典型场景
程序查询全程忙等字/字节简单嵌入式
中断每个事件/数据字/字节键盘、鼠标、中低速设备
DMA初始化 + 结束数据块磁盘、网卡
通道/I/O 处理机启动 + 结束一组数据块大型机、服务器存储

磁盘与 RAID（速览）

磁盘是典型的块设备：寻道时间 + 旋转延迟 + 传输时间构成存取时间。磁盘调度算法（FCFS、SSTF、SCAN、C-SCAN）主要用于减少寻道，属于操作系统 I/O 管理的内容，408 计组可能只考基本概念。

RAID：RAID 0 条带化（性能高、无冗余）；RAID 1 镜像（可靠性高、容量利用率 50%）；RAID 5 分布式奇偶校验（兼顾容量与可靠性，允许 1 盘故障）；RAID 10 先镜像再条带（性能与可靠性兼顾，成本高）。

🚀 进阶深挖（教材级）

深挖 1 · 中断响应为什么必须在指令结束时

若在一条指令执行中间响应中断，指令的中间状态（已修改的寄存器、未写完的存储器）难以保存和恢复，会破坏程序语义。因此 CPU 通常在当前指令执行完后检查中断请求；但某些异常（如缺页）是在指令执行过程中产生的，需要精确记录故障指令地址，处理完后重新执行该指令。

深挖 2 · 中断屏蔽字怎么设

设系统有 4 个中断源，优先级 A > B > C > D。当 CPU 正在服务 B 时，若要允许 A 嵌套、屏蔽 B/C/D，则 B 的屏蔽字应设为：A 位 0（开放），B/C/D 位 1（屏蔽）。屏蔽字通常按“1 表示屏蔽、0 表示开放”设计，具体看题目约定，答题时先写清约定。

深挖 3 · DMA 与 Cache 一致性

DMA 直接写主存时，Cache 中可能还保留旧数据，导致 CPU 读到旧值。解决方法有：DMA 写主存时让 Cache 中对应块失效（invalidate），或采用一致性协议/非缓存区域。408 可能以“DMA 是否需要考虑 Cache 一致性”形式出现，答“需要，需失效或更新对应 Cache 块”。

⚠️ 本章避坑清单

中断隐指令是硬件自动完成的操作序列，不是指令系统中的一条指令。
中断响应第一步是关中断，然后保存断点/PSW、识别中断源；不要先执行服务程序。
中断向量是服务程序入口地址（或入口相关信息），不是中断请求信号，也不是优先级。
中断嵌套由屏蔽字控制，高优先级可打断低优先级；低优先级不能打断高优先级。
DMA 请求的是总线使用权，中断请求的是 CPU 处理；两者触发对象不同。
DMA 传输结束时仍可能发中断，不是“完全不用中断”。
周期挪用是“偷”CPU 不访存的周期，不是让 CPU 完全停机；停止 CPU 访存才是独占总线。
