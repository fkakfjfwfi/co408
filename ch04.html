CHAPTER 04 · 指令系统

第 4 章 · 指令是硬件与软件的“合同”

4.1 指令格式：操作码 + 地址码

📝 生活类比
一条指令像一张快递单：操作码是“做什么”（寄件/退件），地址码是“寄到哪、从哪寄”。有的单子只需一个地址（退件），有的需要两个（寄件人 + 收件人），有的甚至不需要地址（“停机”）。

一条指令通常由操作码和地址码组成。操作码指出做什么操作（加、减、取数、跳转），地址码给出操作数或下一条指令的地址。

格式地址码个数典型用途例子
零地址0空操作、停机；堆栈计算机的运算NOP、ADD（隐含栈顶）
一地址1单操作数运算；一个操作数隐含在 ACCINC A、ADD A（ACC ← ACC + A）
二地址2最常见的双操作数运算ADD R1, R2
三地址3两个源 + 一个目的，互不覆盖ADD R1, R2, R3

指令字长是一条指令的二进制位数，可以等于机器字长，也可以是它的整数倍。定长指令字长便于硬件译码和流水线；变长指令字长可以节省空间，但取指和译码更复杂（x86 就是变长）。

4.2 扩展操作码：在有限位数里塞更多指令

如果操作码固定为 k 位，最多只有 2ᵏ 条指令。想在同样字长里增加指令条数，可以让操作码长度可变：一部分编码留作“扩展前缀”，把地址码字段借来当更长的操作码。

⚠️ 唯一铁律
短操作码不能是长操作码的前缀。否则译码器读到短码时，无法判断这是完整指令还是更长指令的开头。例如 4 位操作码用了 0000~1110，1111 才能作为扩展前缀；扩展出的长码必须以 1111 开头，且不能与任何短码相同。

常见设计：4 位基本操作码，0000~1110 表示 15 条三地址指令；1111 作为前缀，再用下一个 4 位扩展出 15 条二地址指令；1111 1111 再扩展……每层留一个“全 1”作为继续扩展的标志。具体能扩展多少条，取决于还剩多少位可用。

考法：题目给“指令字长 16 位、操作码 4 位、地址码 4 位、要求支持 X 条三地址、Y 条二地址……”，让你判断是否可行或求某字段位数。做法：先满足短码数量，再算剩余编码空间，注意前缀约束。

4.3 寻址方式：操作数到底在哪

寻址方式回答两个问题：有效地址怎么算、取操作数要访存几次。408 常把这两个点放在一道选择题里。

寻址方式有效地址 / 操作数取操作数访存次数特点
隐含寻址操作数隐含在 ACC 或栈顶0指令短，灵活性差
立即寻址操作数 = A0快，但操作数范围受指令字长限制
直接寻址EA = A1简单，寻址范围受地址字段位数限制
一次间接寻址EA = (A)2扩大寻址范围，但多一次访存
寄存器寻址操作数 = R0快，寄存器数量有限
寄存器间接寻址EA = (R)1寻址范围大，寄存器存地址
相对寻址EA = (PC) + A1程序浮动，适合转移指令
基址寻址EA = (BR) + A1程序重定位，BR 由 OS 设定
变址寻址EA = (IX) + A1数组/循环，IX 可变
堆栈寻址操作数在栈顶0 或 1与 push/pop 配合，支持零地址运算
📌 基址 vs 变址：公式像，用途不同
两者都写成 EA = 寄存器 + A，但：基址寻址的寄存器内容由操作系统/程序固定（程序首地址），A 是位移，用于程序重定位；变址寻址的 A 是数组首地址，寄存器内容是变化的索引，用于访问数组元素。做题时看“谁在变”。

相对寻址的 PC 是“下一条指令地址”：取指后 PC 已经更新，所以 EA = 下一条指令地址 + A。A 通常是有符号补码，可向前或向后跳转。若题目给“当前指令地址”，要先加上指令长度再算。

🔬 实验室 · 寻址方式计算器
选择寻址方式，输入 A、PC、R1（以及间接寻址的 M[A]），看有效地址和“取操作数访存次数”。

4.4 RISC 与 CISC：两种设计哲学

维度CISCRISC
指令数量多（几百条）少（几十~一百多条）
指令长度可变定长
寻址方式多而复杂少而简单
访存指令很多指令可直接访存只有 load/store 访存
控制器多用微程序多用硬布线
寄存器较少较多
流水线较难容易
典型x86ARM、RISC-V、MIPS

RISC 的思想是“简单规则，让硬件跑得快”：指令定长、格式少、只有 load/store 访存、运算都在寄存器间进行，便于流水线和编译器优化。CISC 的思想是“让一条指令做更多事”，减少程序指令数，但硬件复杂。现代 x86 内部会把复杂指令翻译成类 RISC 的微操作，两者边界已经模糊。

4.5 从高级语言到机器级代码

408 大纲要求理解“高级语言程序与机器级代码之间的对应”。不需要会写大型汇编，但要能看懂：变量放哪、循环怎么跳、函数怎么调用。

栈帧与过程调用

函数调用时，系统在栈上分配一个栈帧，典型内容包括：

参数：调用者把参数放入寄存器（如 x86-64 的 RDI、RSI、RDX…）或压栈。
返回地址：call 指令把下一条指令地址压栈。
旧帧指针：保存调用者的 RBP，建立当前函数的栈帧。
局部变量与保存的寄存器：函数内部使用的局部变量、被调用者保存寄存器。
返回：leave / ret 恢复栈指针和帧指针，弹出返回地址跳回。

x86-64 中常见约定：整数参数依次用 %rdi, %rsi, %rdx, %rcx, %r8, %r9，返回值在 %rax，栈向低地址增长，%rsp 是栈指针，%rbp 是帧指针。

// C 语言
long sum(long *a, long n) {
    long s = 0;
    for (long i = 0; i < n; i++) s += a[i];
    return s;
}

// 对应的 x86-64 风格汇编（示意）
sum:
    movq    $0, %rax          // s = 0
    movq    $0, %rcx          // i = 0
.Lloop:
    cmpq    %rsi, %rcx        // 比较 i 与 n
    jge     .Ldone            // i >= n 则结束
    addq    (%rdi,%rcx,8), %rax  // s += a[i]（8 字节元素）
    incq    %rcx              // i++
    jmp     .Lloop
.Ldone:
    ret

这段代码体现了三个机器级概念：数组元素地址 = 基址 + 下标 × 元素大小（比例变址寻址）；循环用比较 + 条件跳转；返回值放在约定寄存器。

选择与循环的机器级形态

高级语言机器级实现关键指令
if (a > b) ... else ...比较后条件跳转，两个分支各自成块cmp + jg/jle
while (i < n) ...循环头比较，条件不满足跳出，末尾跳回cmp + jge + jmp
for (i=0; i<n; i++)初始化 + 循环头 + 步进 + 跳回同上，步进用 inc/add
函数调用传参、call、建栈帧、返回call/ret、push/pop

4.6 大小端与边界对齐

大小端

一个多字节数据在内存中按字节存放，字节顺序有两种约定：

方式低地址放0x12345678 的存放典型
大端（big-endian）最高有效字节12 34 56 78部分 RISC、网络字节序
小端（little-endian）最低有效字节78 56 34 12x86、ARM（可配置）

判断技巧：把数据写成 0x12345678，小端就是“倒着抄”：78 56 34 12。题目若给“从低地址到高地址的字节”，按这个顺序写。

边界对齐

很多处理器要求数据的地址是其大小的整数倍：4 字节 int 的地址必须是 4 的倍数，8 字节 double 必须是 8 的倍数。编译器会在结构体成员之间插入填充字节，保证每个成员对齐，并让结构体总大小是其最大成员对齐值的整数倍。

struct S {
    char  c;      // 偏移 0，占 1 字节
    // 3 字节填充
    int   i;      // 偏移 4，占 4 字节
    short s;      // 偏移 8，占 2 字节
    // 2 字节填充（使总大小为 4 的倍数）
};                // sizeof(struct S) = 12

不对齐访问可能导致多次访存、性能下降，某些架构甚至直接异常。408 可能考“结构体大小/某成员偏移”，按“每个成员对齐 + 总大小对齐到最大对齐值”两步算。

🚀 进阶深挖（教材级）

深挖 1 · 扩展操作码的编码空间计算

设指令字长 16 位，基本操作码 4 位，三地址格式有 3 个 4 位地址字段。若要用 15 条三地址指令，操作码 0000~1110；1111 留作扩展。扩展时把第一个地址字段的 4 位并入操作码，得到 8 位操作码，其中 1111 0000~1111 1110 可表示 15 条二地址指令，1111 1111 继续扩展……每层牺牲一个编码作为“继续”标志。计算时牢记：可用的长码数量 = 扩展前缀数 × 2^借用位数 − 继续扩展保留数。

深挖 2 · 为什么 RISC 更适合流水线

流水线要求各段耗时均衡、指令格式规整。RISC 指令定长、寻址方式少、只有 load/store 访存，取指和译码可以并行，寄存器编号位置固定，所以五段流水线容易实现。CISC 指令长度可变、寻址方式多，译码阶段可能很长，流水线需要复杂的拆分和预测。

深挖 3 · 指令级并行与 ISA 的关系

指令系统的设计会影响编译器能否调度、CPU 能否乱序执行。例如定长指令便于取指和分支预测；大量寄存器减少溢出；load/store 分离让访存阶段独立。408 不要求设计 ISA，但会问“某特性对流水线/编译有什么影响”，答题时从“规整性、并行性、访存次数”三个角度展开。

🌐 多源视角
  • 【唐朔飞】把寻址方式按“操作数在指令中/在寄存器中/在主存中”分类，先讲 EA 再讲访存次数。本站用法：做题先问“操作数在哪”，再套公式。
  • 【CSAPP】用 x86-64 讲“程序 = 指令 + 数据”，强调栈帧、寄存器约定和比例变址。本站用法：看到 (%rdi,%rcx,8) 要能还原成 a[i]。
  • 【Patterson & Hennessy】把 RISC 设计总结为“简单指令、大量寄存器、load/store、流水线”。本站用法：RISC/CISC 选择题优先选“定长、少数寻址、只有 load/store 访存”。
参考：唐朔飞《计算机组成原理》第 7 章；CSAPP 第 3 章；Patterson & Hennessy 第 2、4 章。

⚠️ 本章避坑清单

相对寻址的 PC 是下一条指令地址，不是当前指令地址；题目给当前地址时要先加指令长度。
基址寻址的寄存器内容固定、A 是位移；变址寻址的 A 是首地址、寄存器内容变化。不要只看公式一样就混用。
一次间接寻址取操作数访存 2 次（先取 EA，再取操作数），取指另算 1 次；题目问“取操作数”时不要加取指。
扩展操作码必须保证短码不是长码前缀，否则译码歧义。
小端是“低地址放低字节”，0x12345678 写成 78 56 34 12，不是 87 65 43 21。
结构体对齐要算填充字节，总大小还要对齐到最大成员对齐值；不要只把成员大小相加。
