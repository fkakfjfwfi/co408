CHAPTER 03 · 存储系统

第 3 章 · 把“容量、速度、价格”三层叠起来

3.1 存储层次与局部性：为什么 Cache 有用

📚 生活类比
你写作业时，手边的笔是寄存器，书桌上的常用书是 Cache，书架是主存，图书馆是辅存。每次拿书，先看桌上有没有；没有再去书架；再没有才去图书馆。桌子小但快，图书馆大但慢——这就是存储层次。
层次典型介质容量速度成本管理者
寄存器触发器几十~几百字节最快（<1 ns）最高编译器/硬件
Cache（L1/L2/L3）SRAMKB~MB几 ns高硬件
主存DRAMGB几十~上百 ns中操作系统 + 硬件
辅存SSD/磁盘TBμs~ms低操作系统

局部性原理是这套层次能工作的前提：

时间局部性

刚被访问过的数据，很可能马上再次被访问。例如循环变量 i、反复调用的函数、刚查过的页表项。

空间局部性

一个单元被访问后，它附近的单元很可能很快被访问。例如顺序遍历数组、指令顺序执行、结构体字段连续存放。

平均访问时间 Tavg = H × Tc + (1 − H) × Tm
（先查 Cache，缺失再访问主存时：Tavg = Tc + (1 − H) × Tmiss）
加速比 = Tm / Tavg

其中 H 是命中率，Tc 是 Cache 访问时间，Tm 是主存访问时间，Tmiss 是缺失代价。注意“先查 Cache”和“同时查 Cache 与主存”的公式不同，题目会明确。

3.2 主存：SRAM、DRAM 与芯片扩展

三种半导体存储器

类型存储原理刷新读出速度集成度典型用途
SRAM触发器（双稳态电路）不需要非破坏性快低Cache
DRAM电容存电荷需要定时刷新破坏性，需再生较慢高主存
ROM熔丝/浮栅等不需要非破坏性较慢高BIOS、固件

DRAM 刷新：电容会漏电，必须周期性读出并重写。常见三种方式：

方式做法特点
集中刷新在一段时间内集中刷新所有行存在“死区”，刷新期间不能访问
分散刷新每个存取周期都刷新一行无死区，但存取周期变长
异步刷新把刷新分散到最大刷新间隔内折中，死区短

地址复用：DRAM 芯片引脚少，行地址和列地址分两次传送，用 RAS（行地址选通）和 CAS（列地址选通）区分。这也是 DRAM 地址线常为地址位数一半的原因。

芯片扩展：先位扩展，再字扩展

存储芯片的规格常写成“字数 × 位数”，例如 1K×4 位。要组成更大的存储器，需要扩展：

扩展方式目的做法地址线/数据线
位扩展增加字长多片并联，地址线共用，数据线分别接不同位地址线不变，数据线变宽
字扩展增加字数多组串联，地址高位经译码器产生片选数据线不变，地址线增加
字位同时扩展两者都要先位扩展成组，再字扩展成片地址、数据都增加

例：用 1K×4 位芯片组成 4K×8 位存储器。位扩展需要 8/4=2 片并联成 1K×8；字扩展需要 4K/1K=4 组；共 2×4=8 片。地址线：1K 需要 10 位片内地址，4K 需要 12 位总地址，多出的 2 位送 2-4 译码器产生 4 个片选信号。

📌 408 计算套路
① 先算“总字数 × 总位数”；② 用总字数/芯片字数 = 字扩展倍数，总位数/芯片位数 = 位扩展倍数；③ 片数 = 两者乘积；④ 地址线位数 = log₂(总字数)，数据线位数 = 总位数；⑤ 片选译码器输入位数 = log₂(字扩展倍数)。按这五步写，基本不会乱。

存取时间与存取周期

存取时间是从发出地址到数据稳定所需的时间；存取周期是连续两次访问所需的最小间隔，通常大于存取时间（包含恢复时间）。DRAM 的存取周期明显长于存取时间，这是刷新和恢复造成的。

3.3 多模块存储器：让主存“流水”起来

单个存储模块一次只能服务一个访问，CPU 很快、主存很慢。多模块存储器用多个模块并行/流水工作来提高带宽。

方式编址工作方式带宽适用
单体多字一个模块，一次读多个字顺序读出连续多个字提高突发传输效率连续地址访问
高位交叉高位地址选模块一个模块存连续地址，顺序访问仍只用一个模块基本不提高扩大容量
低位交叉低位地址选模块连续地址分布在不同的模块，可流水访问显著提高提高带宽

低位交叉的时序：设 m 个模块，每个模块存取周期 T，总线传送周期 r。连续读 n 个字，第一个字需要 T，之后每隔 r 可以取得下一个字：

t = T + (n − 1) × r   （要求 m ≥ T / r，否则会冲突）
带宽 = n / t

例：4 体低位交叉，T=200 ns，r=50 ns，连续读 4 个字：t = 200 + 3×50 = 350 ns；若每字 4 B，带宽 = 16 B / 350 ns ≈ 45.7 MB/s。若模块数少于 T/r，流水会断，公式要修正。

3.4 Cache：把常用的块搬到手边

Cache 与主存之间以块（line/block）为单位交换数据。主存块要被放到 Cache 的哪一行，由映射方式决定。

三种映射方式

方式规则地址划分优点缺点
直接映射主存块号 mod Cache 行数tag + index + offset硬件简单，只需比较 1 个 tag冲突高，抖动
全相联任意主存块可放任意行tag + offset命中率高，冲突少需与所有行比较，成本高
组相联组间直接，组内全相联tag + index + offset折中，最常用硬件比直接映射复杂
Cache 行数 = Cache 容量 / 块大小
直接映射：index 位数 = log₂(行数)
组相联：组数 = 行数 / 路数，index 位数 = log₂(组数)
offset 位数 = log₂(块大小)
tag 位数 = 主存地址位数 − index 位数 − offset 位数

例：Cache 64 KB，块 32 B，主存地址 32 位。行数 = 2048 = 2¹¹，offset = 5 位。直接映射 index = 11 位，tag = 32−11−5 = 16 位；4 路组相联组数 = 512 = 2⁹，index = 9 位，tag = 18 位；全相联 tag = 27 位。

🔬 实验室 · Cache 映射与命中模拟
固定 32 KB Cache、64 B 块、32 位地址。切换 1/2/4/8 路，输入地址看 tag/index/offset 如何变化；连续访问同一组的不同 tag，观察 LRU 替换。

替换算法与写策略

替换算法

随机、FIFO、LRU、LFU。LRU（最近最少使用）命中率通常较高，但需要为每行维护使用计数；FIFO 简单，可能出现 Belady 异常（增加行数反而命中率下降）。

写策略

写直达：每次写都更新 Cache 和主存，简单但写流量大；写回：只写 Cache，行被替换时才写回，需要脏位。写缺失时还有“写分配/非写分配”两种选择。

组合典型搭配原因
写回 + 写分配常见于 L1/L2利用空间局部性，减少主存写
写直达 + 非写分配常见于简单系统写直达已经更新主存，不必再调入块
写回 + 非写分配较少见写缺失不调块，直接写主存

多级 Cache 与平均访问时间

现代 CPU 通常有 L1（分 I/D）、L2、L3。L1 缺失时查 L2，L2 缺失再查主存。两级 Cache 的平均访问时间可写成：

Tavg = TL1 + m1 × (TL2 + m2 × Tmem)

其中 m₁、m₂ 分别是 L1、L2 的缺失率。注意“缺失率”与“命中率”互为 1 的补数，但多级 Cache 的全局缺失率不等于各级缺失率简单相加。

3.5 虚拟存储器：让每个程序都以为自己有一大块内存

虚拟存储器把主存和辅存统一成一个大的逻辑地址空间。程序使用虚拟地址，硬件/操作系统把它翻译成物理地址；当前用不到的页放在磁盘上，需要时再调入主存。

方式划分优点缺点
页式等长页无外部碎片，管理简单有页内碎片；程序逻辑与页不对应
段式按逻辑段便于共享和保护，符合程序结构有外部碎片，地址计算复杂
段页式先分段，段内分页兼顾逻辑结构与内存管理地址转换需查两次表

页式虚拟地址转换

虚拟地址 = 虚页号 VPN + 页内偏移 offset
物理地址 = 页框号 PFN + 页内偏移 offset
页表项：有效位 + 脏位 + 访问位 + 保护位 + 页框号
查 TLB：用 VPN 查快表。命中则直接得到 PFN，省去访问主存页表。
查页表：TLB 缺失时，按页表基址 + VPN 访问主存页表项，得到 PFN；同时把该项装入 TLB。
缺页判断：若页表项有效位为 0，触发缺页异常，操作系统从辅存调页；若主存已满，按置换算法淘汰一页（脏页需写回）。
拼接物理地址：PFN 与 offset 拼接，访问 Cache/主存。
⚠️ TLB 缺失 ≠ 缺页
TLB 只是页表项的缓存。TLB 缺失只说明“快表没命中”，页仍可能在主存中，查页表即可；只有页表项有效位为 0 才是缺页。这是选择题的高频陷阱。

虚拟存储 vs Cache

维度Cache虚拟存储器
交换单位块（几十~几百字节）页（几 KB）
缺失代价几十~几百 ns几 ms（磁盘 I/O）
管理者硬件操作系统 + 硬件（TLB/页表遍历）
目的弥补 Cache 与主存速度差扩大逻辑地址空间，实现内存保护与共享
写策略写回/写直达通常写回（脏位）

3.6 外存：磁盘与 SSD

磁盘结构：盘片上有同心圆磁道，磁道分成扇区；多个盘面的同一磁道组成柱面。容量公式：

容量 = 磁头数 × 柱面数 × 每道扇区数 × 扇区大小

存取时间由三部分组成：

存取时间 = 寻道时间 + 平均旋转延迟 + 传输时间
平均旋转延迟 = 1 / (2 × 转速)，转速单位：转/秒

例：7200 r/min = 120 r/s，平均旋转延迟 = 1/(2×120) s ≈ 4.17 ms。传输时间 = 数据量 / 数据传输率。

SSD：基于闪存，没有寻道和旋转延迟，随机访问快、抗震、功耗低；但有擦写次数限制，需要磨损均衡、垃圾回收。RAID 0 条带化提高性能无冗余；RAID 1 镜像；RAID 5 分布式奇偶校验，兼顾容量与可靠性；RAID 10 先镜像再条带。

🚀 进阶深挖（教材级）

深挖 1 · 直接映射的“抖动”

直接映射中，主存块只能进唯一一行。如果程序反复访问两个映射到同一行的块（例如数组跨度正好等于 Cache 容量），每次都会互相替换，命中率骤降，称为“抖动（thrashing）”。组相联通过“一组多行”缓解这个问题；全相联则完全不限制，但比较成本高。

深挖 2 · 写分配与非写分配

写缺失时有两种选择：写分配先把块调入 Cache 再写（适合写回，利用后续写/读的局部性）；非写分配直接写主存，不调块（适合写直达，避免无谓的读）。考试常问“写回法通常搭配哪种”，答“写分配”。

深挖 3 · 虚拟地址到物理地址的完整路径

CPU 发出虚拟地址 → TLB 查 VPN → 命中得 PFN；未命中查页表（可能多级）→ 得到 PFN 并填入 TLB → PFN + offset 得物理地址 → 查 Cache（物理索引/物理标签）→ 命中返回；未命中访问主存。若页表项无效 → 缺页异常 → OS 调页 → 重新执行指令。把这条路径画成流程图，大题就能按步拿分。

🌐 多源视角
  • 【唐朔飞】把 Cache 映射讲成“主存块号对 Cache 行号的函数”，直接映射是取模，组相联是先分组再取模。本站用法：先写“行数/组数”，再取 log₂，地址划分就不会错。
  • 【CSAPP】用“存储层次 + 局部性”统一 Cache 和虚拟存储，强调“命中时间 + 缺失率 × 缺失代价”。本站用法：平均访问时间题先判断是“先查 Cache”还是“并行查”，再套公式。
  • 【操作系统】虚拟存储的核心是“按需调页 + 页面置换”，TLB 只是加速器。本站用法：不要把 TLB 缺失和缺页混为一谈。
参考：唐朔飞《计算机组成原理》第 3、4 章；CSAPP 第 6、9 章；王道《计算机组成原理复习指导》第 3 章。

⚠️ 本章避坑清单

Cache 行数 = 容量 / 块大小，不是容量 / 字大小；地址划分先算行数/组数，再取 log₂。
直接映射的 index 是“行号”，组相联的 index 是“组号”；4 路组相联时组数 = 行数/4。
tag 位数 = 主存地址位数 − index − offset，不要忘记 offset。
低位交叉提高带宽，高位交叉主要扩大容量；不要把两者说反。
低位交叉公式 t = T + (n−1)r 有前提 m ≥ T/r；模块数不够时会冲突。
TLB 命中不需要查页表，但仍可能要访问 Cache/主存取数据；TLB 缺失不等于缺页。
虚拟存储的交换单位是“页”，Cache 的交换单位是“块”；两者管理者不同（OS vs 硬件）。
